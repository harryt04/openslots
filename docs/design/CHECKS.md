# Design checks

Every numbered acceptance check of the [design spec](openslots-design.html), and rules T-1 to T-6 for each screen, with a status and the evidence for it. Last updated 2026-11-17 for the v1 build.

**Summary: 81 Met, 20 Met with a difference, 0 Not met, 2 Not verified.** "Not verified" means it can only be confirmed with a real Google account, which this build has not been run against.

How the statuses were reached:

- Functional checks cite the automated test that asserts them.
- T-4 (contrast), T-5 (state never by color alone) and T-6 (focus ring) come from a scripted pass over 38 screen states in light and dark at 1280px and in light at 390px: measured contrast of rendered pixels, the computed outline of every Tab stop, and a screenshot of each state with color removed (achromatopsia emulation). The script over-reports, so its flags were then judged by hand; what was a false positive and why is written out under "Measured contrast" and "Focus and keyboard". The orchestrator looked at the no-color screenshots for sign-in, Bookings, Services, the service editor, Availability, Calendars, the hosted booking steps and the manage page.
- The fixture approximates the spec's salon: it has no date overrides, second schedule or rescheduled booking, and service colors and rules differ from the spec's. Those states were checked in their own slices' reviews (see each slice's pull request) but not re-photographed here.

Known gaps in this pass: the invalid-hours state on Availability and one mode of the manage page were not reached by the script; the screenshots named `S6-reconnect` and `S2-calendar-banner` were taken before the broken connection took effect, so they show every account connected and no banner (the reconnect state is visible in `S6-no-booking-calendar`, and the banner has test coverage but no picture); the no-color screenshots exist in light mode only, and in dark mode the destructive and accent tokens are close in hue, so destructive actions rely on their labels there; the "No booking calendar" state was photographed with a booking calendar still present, so that state has test coverage but no picture; text inside the gallery's iframes was not re-measured.

Phone is required when requested. Overlapping self-reschedules are refused. Calendars omits per-calendar color dots. Fake sign-in has a labelled test link. Fixture approximations: services use default colors/rules except duration; default timezone is retained. Weekly hours approximate the salon, but override types and second schedule rely on availability.spec.ts evidence rather than the screenshot fixture. Two API bookings seed the list; no seeded rescheduled booking. The fixture sends a top-level note instead of customer.notes, so it does not seed a persisted booking note. No real Google services used.
