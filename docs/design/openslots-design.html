MIT · self-hosted · Google Calendar

Open time slots for every business you run.

One place to sign in with Google, link calendars, define services of any length, and set bookable days. Your other apps install the picker from npm and customers book into the gaps. This page is the target implementation agents build and check against: every screen has an ID and acceptance checks. Switch themes and modes in the top bar; the booking mockups are clickable.

Vercel's structure (Geist type, tight spacing, hairline borders, generous white space) with color doing real work instead of grayscale. AnalyticsPostHog, off unless a key is setSelf-hosters should not phone home by default.
Adjustment 1pnpm workspace: apps/web, packages/react, packages/coreRequired to publish components to npm from the same repo. core holds the slot engine and shared types.
Adjustment 2Vitest and Playwright addedThe scaffold has no test runner. Slot math and booking races need tests.

No double booking, on MongoDB

Each booking also inserts one small "lock" document per 5 minute block it occupies, buffer included, into a collection with a unique index on business + block. Two customers racing for overlapping times cannot both succeed: the second insert fails, its partial locks are removed, and that customer sees S8-4. This works on a standalone MongoDB with no transactions, which matches the scaffold's stated constraint.

Google is asked at two moments

When listing slots (free/busy for the visible range, cached about a minute) and again immediately before confirming a booking. Then the event is created with the customer as a guest, so Google sends the invitation and v1 needs no email server.

Not in v1

Payments, several staff per business, round robin, Outlook or iCloud, SMS reminders, recurring appointments. The data model leaves room; none are built.

Slices sharing a number run in parallel. Each runs in its own Treehouse worktree and ends in a pull request; nothing merges, publishes or deploys without the maintainer. Every builder is given this file and must open the app with agent-browser and tick its screen's checks before opening the PR.

One setup trap to design around

Each self-hoster creates their own Google Cloud OAuth client. If it is left in Google's "Testing" state, Google expires the calendar connection every 7 days. The self-host guide must walk through publishing the client, and S6's "Needs reconnect" state exists for when someone skips that.
